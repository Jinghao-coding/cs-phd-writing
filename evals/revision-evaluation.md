# 修订行为评估

用于维护技能、比较修订方案或评估可选工具。普通写作无需运行整个评估集。

## 材料与划分

- [C1–C62](cases.md)：独立构造的输入；[验收条件](acceptance.md)描述行为，不要求固定措辞。
- [R1–R2真实修订分析](real-revision-analysis.md)：同一篇公开论文在IteraTeR中的两类改动，用于区分清晰性修订与含义变化；不把两个切片当作两篇独立论文。
- 新真实案例应记录公开来源或作者授权、版本/提交、段落位置、原稿与修订、意图及证据。不要将私人论文或学校个案默认发布。
- 按论文或项目划分开发样本和保留样本，不能把同一论文相邻段落拆到两侧；保留样本不用于调规则。来源领域须分别记录，考试、二语作文与系统论文分开报告。

## 评估过程

先固定skill版本、输入、任务范围和可用材料，再保存实际输出及改动。独立评估者只拿任务和必要证据，不提前拿验收答案；只有已获委派授权时才使用子代理。维护者人工情境自查与独立执行分别登记。

每个输出按下列维度评价，分别给出具体证据，不合成为含糊总分：

| 维度 | 判断 |
| --- | --- |
| 问题修复 | 原问题已解决、部分解决或仍存在；依据预先定义的完成条件 |
| 技术含义 | 实体、动作、条件、数字、范围、因果、来源归属是否保持；合法更正另记依据 |
| 可读性 | 修改后信息承接是否更清楚，是否引入断裂；允许持平 |
| 过度修改 | 正确文本被判错、术语被替换、范围被扩张、反复风格改写分别计数 |
| 文档完整性 | 公式、标签、引用键、宏和代码是否得到保护或正确同步 |

成对比较时可隐藏版本名称并交换左右顺序，评价改善、持平、变差并解释原因。模型评语作为辅助意见，存在分歧时回到输入与证据；作者修改也不自动成为唯一正确答案。

编辑级精确率/召回率适合明确的纠错任务；采用ChERRANT时记录版本和多参考答案。段落重组应按论证关系评价。字面匹配、BLEU、禁词数、句长、引用数量都不能单独判断学术质量。正确文本负例应报告被误改的数量与总量。

## 多参考与停止条件

等价说法只要保持技术含义且解决原问题都可接受。C49给出数值换算的不同答案，C44/C48提供保留原文的负例。修改产生新错误时回退或局部修复；同一问题已解决且无新增证据时停止，不重复追求风格变化。

## 自动检查与记录

执行 `python3 evals/test_revision_check.py` 验证只读差异工具，再使用 `scripts/check_revision.py`检查实际改写文件。工具不覆盖的条件和论证由上述分项核对处理。

一次运行记录至少包含：日期、版本、方式、案例ID、实际输出、分项判断、定位证据和修复决定。长期保留稳定案例与版本验收摘要，临时日志和中间稿按宿主项目约定清理。新增失败以针对性案例回归，不扩大为无关全局规则。
