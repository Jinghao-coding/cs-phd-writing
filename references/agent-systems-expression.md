# Agent 系统的上下文与表述

用于撰写智能体、工具调用、推理服务、工作流编排及其资源管理。按当前实现和证据解释对象，不把教程或其他系统的能力写入当前研究。一般系统表述见 [系统上下文表达](systems-context-expression.md)。

## 先读执行过程

从实际应用任务出发，定位消息与状态、模型调用、工具或其他角色调用、结果回传、下一轮输入、终止条件。核对每一步由谁触发、输入何时确定、失败或超时如何处理。可能的运行过程不等于每次都会执行的固定流水线。

| 易混对象 | 写作时需要确认 |
| --- | --- |
| Agent / 角色 / 模型实例 | 角色是逻辑职责还是独立服务？是否共享权重或后端？多角色不推出多模型、多GPU或并行执行 |
| 应用任务 / LLM请求 / 工具调用 | 一项任务包含多少次动态调用？重试、反思和分支是否影响调用次数与完成条件？ |
| 计划 / 执行图 | 哪些边已确定，哪些依赖工具结果或模型输出？有循环时，区分控制流图与某次有限展开的调用实例图 |
| 应用记忆 / 检索材料 / KV cache | 分别存储什么、由谁管理、生命周期和复用条件如何？共享文本不等于共享KV |
| 语义压缩 / 状态卸载 | 摘要或截断可能改变后续输入；迁移物理缓存的语义与正确性取决于实现，不能统称为无损压缩 |
| 任务规划 / 资源调度 | 谁决定下一步动作，谁执行模型选择、准入、放置或设备资源分配？框架编排不自动提供这些资源能力 |
| 通信协议 / 执行保证 | 接口互操作不自动保证截止时间、恰好一次、容错或最优调度；按协议版本与实现核查 |
| 工具等待 / 资源释放 | 等待工具并不说明GPU空闲、请求结束或KV可删除；确认并发工作和状态保存方式 |
| 应用质量 / 系统效率 | 任务成功率、正确率与端到端时延、token量、费用、显存、GPU时间分别报告，不能互相替代 |

调度策略只能利用实际可得的信息。未来工具结果、内部推理过程、最终调用次数不可因论文叙事需要而假设已经可见。预测值、历史统计与观测值要区分。

## 根据证据改写

以下为合成情境，不是对特定框架的实测描述。

原句：“多智能体并行协作，通过共享记忆降低GPU开销。”

材料A仅表明三个角色顺序调用同一个模型，并传递工具返回的文本。可写：“系统依次调用三个角色，并将前一阶段的工具结果加入后续模型请求的上下文。”不能补上并行、KV共享或资源收益。

材料B表明两个独立请求并发运行、复用相同前缀的物理KV块，并测量了显存占用。应按材料写明并发请求、缓存匹配与有效性条件，再给出同一负载、同一基线下的显存结果；不能据此推导端到端时延必然下降。

原句：“规划器生成DAG后，调度器获得所有阶段输入。”

若后续阶段输入包含尚未返回的工具结果，可写：“规划器提供候选阶段及依赖关系。工具结果返回后，运行时构造相应阶段的输入。”若存在循环，不能无条件将完整控制流称为DAG。

## 研究概念与引用

ReAct、Reflection、Plan-and-Solve 等首先核对具体论文和本实现：通用反思循环不等于某篇方法的全部机制；规划提示不必然是独立模型服务；语言反馈不等于参数训练。MCP等协议用官方版本文档支撑接口说明，性能与正确性结论另需实验证据或证明。

教程用于概念导航，原论文用于研究归属和机制论断。可从 [Hello-Agents](https://github.com/datawhalechina/hello-agents) 第4、8、9、10、12章定位相应主题；不声称教程全部内容已核验或示例已复现。这里的检查表与示例独立编写，没有收录教程正文、代码或图片。参考链接核对日期：2026-10-04。
