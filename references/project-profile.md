# 项目接入与规则来源

把学校和个人研究的事实保存在论文项目中。技能包只保留通用流程及读取约定，便于公开分发和跨项目使用。

## 发现配置

以用户正在处理的论文目录为项目根目录，读取其适用的项目说明。推荐配置文件为 `docs/thesis-writing-profile.md`，也可由用户或 `AGENTS.md` 指向其他文件。

Claude Code 项目也可在 `CLAUDE.md` 中指定同一份配置。两种平台共用论文项目内的材料和配置。

技能安装在另一个论文仓库内，不代表该仓库就是当前用户的论文。不要读取安装目录上级的个人资料作为默认配置。

没有配置文件时，从当前请求和已有材料取得必要信息。先完成不受影响的工作，不创建固定问卷。用户要求建立长期工作环境时，可新建配置并填入已经确认的事实。

## 首次接入

1. 定位当前项目已有的学校规范、模板、范文及研究材料。用户只提供网页时，核对官方原文的版本和适用范围；只有模板时，不把模板示例推定为全部规范。
2. 复用已有记录。需要建立配置时，从 [项目模板](../assets/project-template/) 选择所需文件，将 `docs/` 中对应内容放入论文项目的 `docs/`；已有同名文件只合并缺少的信息，不用空白模板覆盖。
3. 在 `docs/thesis-writing-profile.md` 中登记已确认信息和资料路径。学校条款记录在 `docs/university-writing-spec.md`；范文的观察与拟采用做法记录在 `docs/reference-thesis-notes.md`；个人偏好直接写进配置。
4. 将 [项目说明片段](../assets/project-template/project-instructions.snippet.md) 中适用的内容合并进项目 `AGENTS.md` 或 `CLAUDE.md`。需要整合小论文时，再使用 `docs/paper-to-thesis-map.md`，不要求每个局部润色任务都建立该表。
5. 以当前任务试读配置，检查指向的文件是否存在、哪些是正式规范、哪些是参考或偏好。只报告会影响本次工作的缺项；未确认信息留空，正文继续按已知依据处理。

学校原件和范文可以放在 `materials/university/`、`materials/reference-theses/`，也可沿用现有位置。路径以论文项目为基准；资料是否进入 Git 或 Overleaf 由项目规则决定。项目配置放在论文目录中，更新技能本身时无需覆盖这些文件。

## 配置内容

配置文件可按下面的主题组织；缺少内容可以省略或标明待确认，不猜测填写。

| 主题 | 应保存的信息 |
| --- | --- |
| 身份与研究 | 学位类型、学科、正文语言、已确认题目、研究对象 |
| 源码与材料 | 主文件、模板、资料目录、导出目录、同步范围 |
| 规范来源 | 官方 URL/文件、版本、适用批次、核验日期、原文定位 |
| 个人偏好 | 篇幅规划、表达风格、明确保留的术语或结构 |
| 章节决策 | 已确认的安排与仍可调整的部分 |
| 材料状态 | 指向已有材料索引、成果版本和证据记录，避免复制一份很快过时的表 |
| 参考写法 | 师兄论文或其他范文的分析笔记与来源 |

使用相对项目根目录的路径；全文资料、私人链接、个人信息和学校文件无需复制进可发布的技能包。

## 分清规则性质

- **正式规范：** 提供发布者、版本、适用范围和原文定位。模板是实现载体，样例中的占位文字不是要求。
- **用户/导师安排：** 记录谁确认及适用项目。学校规范与安排出现实质冲突时说明冲突，不能静默声称二者同时满足。
- **参考写法：** 说明来自哪篇范文及采用理由，不标为强制规定。
- **规划参考：** 页数、章数和写作节奏等可以迭代，不伪装成所有学校共同标准。

论文题目、学位类型和个人偏好不能从模板示例推测。正式规范中的“应、须、一般、宜、可”等表述要保留其约束程度，不把建议升级为硬门槛。

## 更新规范

模板、学校通知与标准版本分别记录。出现新文件、版本冲突或进入正式提交阶段时，核查原始发布渠道及适用批次；一般段落润色不必重复联网检查。

若格式规定不明确，保留当前模板并说明尚未核查的项目；已知语言和研究事实仍可继续处理。不能将另一所学校的摘要长度、页数、图表样式和提交程序迁入本项目。
