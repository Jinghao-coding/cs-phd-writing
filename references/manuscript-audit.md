# 全文、图表与提交前审阅

先确定用户选定版本、审阅范围和实际可读内容。用户只给一章时只评价该章及已提供上下文；要判断全文完整性，需要读取相关目录、正文、附录、参考文献及项目规范。

## 问题与证据的对应

核对题目、研究问题、章节功能、方法、证据、贡献与结论是否相互对应。区分遗漏、重复、矛盾和可调整的组织选择；不把并列研究误判为必须递进，也不把综述章缺少实验当作错误。

## 文档对象检查

| 对象 | 实质检查 |
| --- | --- |
| 图与表 | 正文实际引用、编号与题注、坐标和单位、数据口径、来源及可读性；正文数值与图表是否一致 |
| 公式与算法 | 定义和假设、符号含义、上下标、正文引用与推导关系；修改符号时检查所有相关位置 |
| 附录 | 正文承诺的证明、补充实验或材料是否实际存在；引用位置是否正确；附录是否确实支持所引判断 |
| 脚注与尾注 | 注号、所附位置、内容、来源与交叉引用是否匹配；是否遗漏了影响理解的限定 |
| 引文与参考文献 | 引用可定位、条目真实、来源支持论点、重复条目及著录一致性；真实性和格式分别判断 |
| 中英文版本 | 摘要、标题、关键词及相关段落的研究对象、贡献、数值、条件和确定性是否一致；允许符合摘要功能的合理压缩 |

文本抽取不足以核验图形、公式、修订或版式时，使用对应文档或页面工具。没有原始数据不能宣称已复现实验；只核对了条目格式不能宣称全部引文事实已验证。

## 答辩或提交前

读取当前学校适用规范，按正式要求核对前置材料、正文、结论、文献、附录及成果说明等组成部分。学校没有要求的项目不擅自升级为必交项。

核对封面等已确认信息、摘要对应、目录和交叉引用、必需文件、模板版本以及实际导出 PDF。发现尚未确认的字段或缺失材料时，在审阅报告中明确影响，不猜填身份信息或声称已满足全部提交要求。

正文应呈现研究内容；修稿过程、材料待办和项目状态移到维护文档。科学结论必需的条件与局限保留在相应论述中。

## 审阅结果

整章或全文审阅可按用户要求生成 Markdown 报告，包含：实际版本与已读范围、需要修改的具体问题、原文位置、依据、建议改写或处理方式，以及尚无法判定的事项。范围较小时直接给出对应意见，不强制创建长报告。

区分事实或逻辑错误、语言问题、格式要求和可选风格建议。只报告实际发现的问题；不得用任意分数、禁词次数或“AI 痕迹”标签代替依据。报告是审阅结果，不能冒充已经完成修改或已获学校认可。
