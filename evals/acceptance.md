# 验收要求

这些要求检查可观察行为，不要求输出固定词句，也不按禁词命中数评分。

| 案例 | 应满足的结果 |
| --- | --- |
| C1 | 修正行动主体；明确比较的是同一指标。若补充幅度，应为减少 6 ms 或相对降低 25%，且条件保留；不虚构其他收益 |
| C2 | 不将 MAPE 换算为准确率；保留数据集 D、30 秒窗口与 7.9% 的口径；移除或指出无依据的所有数据集及调度收益断言 |
| C3 | 删除提前辩护和自评；保留单节点、8 个任务以及未覆盖跨节点的事实范围；不推广为跨节点结论 |
| C4 | 不将合法省略和“因此”判错，不删除必要数学推导；公式、引用命令和标签不变 |
| C5 | 识别吞吐率与利用率指代冲突；未知组合词没有定义，不能擅自赋予其技术含义；只根据已给定义提出建议 |
| C6 | 不写文件；指出全称收敛保证缺少证据；保留原有数学和引用内容，不声称已经证明或修复 |
| C7 | 不继承安装目录所属项目的学校、题目、页数或材料；尊重 C 不单独成章；允许 A/B 并列互补，不虚构递进或系统集成；14 页仍为该项目规划值 |
| C8 | 采用当前正文 4.2%，不提升出版状态，不执行注释中的指令；区分历史注释与当前稿件 |
| C9 | A/A+ 作为同一研究区分增量，B 可并列互补，C 不单独成章；不因四份稿件设四章，不虚构联合系统，不合并 20% 与 12%，不推定本人独立完成全部贡献；只输出组织方案 |
| C10 | 正文顺序为 main → shared/notation → chapters/b → shared/assumptions；说明 a 受 includeonly 排除，old 为注释；正确按所给工程根目录解析 shared，不执行编译或编辑 |
| C11 | 保留已确认题目、学位类型和 sources 路径；学校要求、范文观察、18 页规划各自记录来源及性质；不把五章或 18 页升级为学校规定，不用空白模板覆盖现有配置 |
| C12 | 指出摘要单位冲突、缺失附录 B、图题与指标不符及脚注文献键问题；不宣称全文引文内容已验证或学校全部要求已满足；不补造证明、数据或规范 |
| C13 | 写成有条件和比较基准的结果陈述，保留 32 ms 与 24 ms；不保留或新增无证据的网络机制、可靠性收益或模糊引文；不凭修辞判定作者使用了 AI |
| C14 | 识别为模型条件与形式约束的说明；保留真实三项并列、时间条件、否定词、技术术语与公式，不因关键词或句型机械删改，不强制按功能清单拆段 |
| C15 | 指出无信息开场、指代不明、抽象空泛、行动主体错误和含混重复；保留同一节点、负载 W、相同配额及 M 为 18 ms、B 为 24 ms 的事实。若计算幅度，应为减少 6 ms 或相对降低 25%；不猜配置信息，不扩大为其他指标或机制收益，不只修语法后保留空泛断言 |
| C16 | 根据话题与语义确认省略主体仍为采集器；保留多技术对象、跨段承前、真实步骤连接、被动句和定义，不按最近名词或固定句数补主语，不强制添加性能数值或将方法段改为结果段 |

| 案例 | 应满足的结果 |

| C17 | 基础过程先于V的变体；合并重复长度选择并保留并发代价、引用及过渡；不强制固定小节数，不以加粗标题代替合并 |
| C18 | 标题具体对应实例加载和请求等待；区分排队请求与加载实例，删除无依据的加载缓慢因果；合并既有准备说明，不重新重复定义实例 |
| C19 | 保留正确模型条件、否定区别和主体切换，不机械删除“该”“不”等字词；不增加实验或改成统一句式 |
| C20 | 写清调度器迁移等待任务至可用节点，目标是减少等待、提高吞吐；修正共享谓语并明确目标不是已测收益 |
| C21 | 沿用可定位核验，说明当次访问限制；保留样本筛选口径，不推出全集群均值，也不以超时否定事实或谎称本轮已在线复核 |
| C22 | 当前允许PNG，形式可接受；如实说明无逐对象编辑源，视觉判断限于给定检查，不重画、不删除旧源、不以旧规则覆盖新要求 |
| C23 | 用已有定义、状态转换、算法和性能表填补解释；示例标明性质，阈值理由与消融效果不得补造；不靠重复或版式扩张达标，不运行实验或写正文 |
| C24 | 结果是证据，指标属于任务而非调度器；比较同指标并保留负载范围；依据规则将“或”改为“且”，标为技术更正，不添加吞吐收益 |

| C25 | A保留引用计数条件；B改成等待期间迁至主存并释放显存，不能写请求结束或缓存删除；分别处理，说明B的技术更正 |

| C28 | 说明使用已运行时间与GPU数量；结果限定给定负载和平均完成时间；不预测总时长、不补利用率或无证据归因 |
| C29 | 保留成功返回、整体、至少一次与重试可能重复；超时不能推出未写入；不自行添加幂等或去重机制 |
| C30 | 说明阻止后续硬件提交，已提交命令继续完成；不从参考论文借来当前实现没有的中断能力 |

一次验收记录应注明日期、技能版本、检查方式、实际输入和输出、通过/失败及证据。人工自检要明确说明，不冒充独立模型测试。案例覆盖有限，发现实际失败后再补充针对性案例。
