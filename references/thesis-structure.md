# 总论点、绪论与章节组织

改写说明（2026-09-05）：改写上游结构规则，移出学校专属要求并调整研究章和推导的处理。来源及修改见 [上游改写记录](upstream-adaptation.md)。

## 从完成的研究形成主线

梳理研究对象、核心问题、已完成方法、已有证据和各项贡献。题目及章节约束从项目读取，不能把旧开题中的研究计划直接视为完成的研究。

多成果论文优先回答：各项工作共同面对什么问题，各自处理哪个层次或条件，各章提供什么新知识。成果关系可以并列、互补或递进；只在有依据时描述依赖。

每个候选研究章写出：所回答的问题、为什么需要该研究、方法及证据、与其他章节的关系。综述、方法、系统和结论章各有功能，不强制综述章也提出新的实证结论。

## 成果如何进入论文

| 情形 | 可采用的组织方式 |
| --- | --- |
| 独立问题、方法与证据完整，且服务于总论点 | 候选研究章 |
| 多篇稿件围绕相同问题或为会议/扩展关系 | 合并梳理，区分基础和新增内容 |
| 同一工作覆盖多个研究问题 | 按论证需要使用，避免重复计算贡献或重复报告同一实验 |
| 前期研究或方法基础 | 在相关章节说明其作用和来源 |
| 与主线联系有限 | 按学校要求列入成果、附录或不纳入正文 |

已确认的章节安排优先执行。不能因新收到一篇论文就自动增设一章，也不能为了维持旧章数补造工作。

## 绪论的充分性

充分展开以下内容：

- 具体研究背景、变化或现象及其产生的研究问题。
- 研究对象、概念和范围，区分容易混淆的层次。
- 已有研究解决了什么、尚有哪些不足，以及这些不足为何重要。
- 总问题如何分解，各研究内容分别解决什么。
- 有证据支撑的贡献及其联系。
- 全文组织，必要时用研究关系图帮助定位。

篇幅由项目目标、模板、学科和论证需要共同决定。用户给定的页数是该项目的约束或规划值，不能推广为所有博士论文的最低要求。检查是否展开充分，同时识别重复背景和无信息扩写。

若另设相关研究章，绪论提供问题地图和整体切入点，后者展开主题比较、证据与方法差异。两章允许必要重述，但不要大段重复。

## 研究章的可选组织

系统与工程类研究常采用：问题与观测、建模与设计、方法、实现及实验、小结。定量、定性、理论、设计及混合研究按其证据形式调整，不强制统一成某一学科的模式。

- 方法：明确对象、输入、输出、假设、决策变量与必要步骤，说明设计理由；有理论推导时保留完整逻辑。
- 实验：提出要检验的问题，交代环境与对比方法，报告结果，解释能回答什么；消融、开销和扩展性只写实际完成部分。
- 系统：说明实际实现、接口与验证，不用一张框架图代替集成证据。
- 小结：回答本章问题。与下一章有真实未解决问题时自然衔接；并列研究不必虚构“前章不足导致后章”的故事。
- 结论：回到全篇问题，整合已验证贡献、条件和后续问题；不新增未经正文论证的结果。

章标题用研究主题表达功能，避免仅堆系统名。相邻标题的粒度和逻辑层级相称，层级深度遵守项目规范。

## 参考其他博士论文

分析其问题分解、研究层次、章间衔接、证据组织和图表作用，并注明来源定位。分别记录“观察到的做法”和“拟采用的做法”。

参考论文不自动提供当前学校规范，也不意味着其章数、页数、方法和数据适用于当前研究。不能把参考图中的关联直接复制成自己系统已实现的接口。
