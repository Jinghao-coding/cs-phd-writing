# 参考文献核验、导入与学校格式适配

用于引文核验、从 Google Scholar / IEEE / ACM 等导入 BibTeX、统一引用键，以及引用软件、网站、数据或标准。三个结果分别报告：**来源真实且版本对应、来源支持正文论断、输出符合当前学校规范**。格式正确或 DOI 可解析均不能单独证明前两项。

## 1. 读取学校要求与现有实现

先从当前项目配置定位正式学校文件，实际读取参考文献相关条款及示例，记录版本、适用批次、页码。不要只读规范摘要或沿用另一所学校的规则。

核对：正文标注方式与位置、排序方式、作者姓名显示与截断、题名及刊会名称、类型/载体标识、卷期页码、DOI/URL、电子资源日期、字体缩进等。学校没有明确的事项与项目约定分别记录；参考文献数量、引用键命名也不能凭模板样例推成校规。条款互相冲突时定位差异，不声称已经全部符合。

确认当前工程入口、文献库、引用宏、样式文件及后端：

- BibTeX + `.bst` 与 biblatex + Biber 的字段和入口并不完全相同。先读实际样式、文档或做最小样本验证，不因文件扩展名都是 `.bib` 就混用。
- BibTeX 保存书目数据；作者截断、姓名大写、标点、排序等通常由样式产生。不要为了显示前三位作者而删除完整作者名单，也不要把 `[J]`、`[C]` 等直接拼进题名。
- 使用学校已指定的样式。外部样式项目是实现参考，不自动替换现有模板，不因出现较新国标或宏包版本就推定学校已经切换。
- 只有文件明确要求或当前样式确有缺项时才调整配置，并用实际输出验证。不要直接编辑会被重新生成的 `.bbl` 作为持久修复。

## 2. 导入前核验真实身份

Google Scholar 等导出用于发现候选记录；IEEE、ACM等出版平台的导出也要与选定出版版本核对。已有可追溯核验记录可以复用。

1. 从 DOI、官方出版页、论文首页或正式会议目录定位记录；辅助查询 Crossref、DBLP、arXiv 等。DOI 要解析到**同一题名、作者和版本**，不是仅返回成功。
2. 逐项比较题名、完整作者名单及顺序、发表载体、年份、卷期、页码或文章号、DOI、版本。遇到在线优先与正式卷期年份不同，明确采用版本，不拼接元数据。
3. 作者顺序按所引版本保留，不按姓氏排序。核查复姓、姓名前缀、后缀、重音、团体作者和姓名缩写；找不到全名时保留经核实的缩写，不凭首字母扩写。
4. 会议论文、期刊扩展版、预印本、勘误或撤稿记录分别辨认。不能把arXiv题名和作者、会议年份与期刊DOI组成一个条目。发表状态或更正影响当前论点时相应说明。
5. 阅读支撑正文论断的原文位置。只有摘要或元数据时如实登记，不声称全文支持已确认。软件文档不能代替性能实验，项目宣传页不能独立证明研究优越性。

找不到来源时标为未核实或元数据冲突，保留已有证据和检索范围；不能猜作者、年份、页码、出版地或 DOI，也不能因一次访问失败判定文献伪造。无 DOI 的真实文献仍可通过官方记录等核验。已经核实的内容与尚缺字段分别记录。

## 3. 无损规范字段

保留原始导出或可恢复差异，再对核验后的记录做规范化。批量操作采用理解 BibTeX 结构的解析器或成熟工具，不用按逗号分割、单条正则等方式重写嵌套花括号、姓名或宏。

| 对象 | 处理规则 |
| --- | --- |
| 条目类型 | 按实际出版对象及后端支持选用：期刊论文、会议析出论文、专著、学位论文、报告、电子资源等；有URL不自动变成网页 |
| 作者 | 各作者用 `and` 分隔；在可确认姓名结构时采用 `Family, Given`；团体名称按解析器规则整体保护，如 `author = {{Example Research Group}}`；不手工加入 `et al.` 替代已知作者 |
| 题名 | 保持原题语言与含义，清理确属导出错误的转义；必要时用花括号保护GPU、LLM等专名大小写，不全文强制小写 |
| 刊会名称 | 核对官方名称及学校全称/缩写要求；`journal` / `journaltitle`、`booktitle` 等根据后端映射，不能靠重命名丢失语义 |
| 页码与文章号 | 页码范围与eLocator/article number分别保存；不把文章号扩展成假页码，也不把PDF页数当出版页码 |
| 时间与版本 | 出版年、在线发表日、更新日、访问日各有含义；`year/month` 与 `date` 按样式兼容性转换；访问日期是真实访问日期，不是运行脚本的默认日期 |
| DOI与URL | 核验身份后清理冗余DOI前缀；保留有效URL中的必要参数和大小写，不因“清理”破坏版本定位；按校规与样式决定显示哪些字段 |
| 未识别字段 | `version`、`urldate`、`eid`、`eprint`、`mark`等支持范围因样式而异；检查输出是否丢失，采用有依据的兼容字段或局部样式配置，不静默丢弃版本/访问日 |
| 缺项 | 缺项状态进入核验报告；确需输出“不详”等著录形式时依据校规和样式，不自行推测元数据填空 |

数据库中保留完整事实，样式中实现呈现。不是将IEEE导出文本替换标点就完成学校格式转换。

## 4. 统一引用键与去重

沿用当前项目稳定约定。用户要求统一时，无既有约定可选 `firstauthorYYYYkeyword`（例如合成键 `lin2024scheduler`）；机构作者采用稳定短名。相同候选键用可区分主题或稳定后缀消歧。无已知年份时不猜年份；采用有记录的替代键。引用键是内部标识，不决定正文编号或文献排序。

- 建立旧键→新键映射，处理大小写与冲突后，再更新所有有效入口可达的引用命令、`nocite`、自定义引用宏、跨文件引用及 `crossref/xref/xdata/entryset/related` 等实际使用的键字段。不要全文无差别替换普通单词、URL和无关标识。
- 生成器应保持幂等，已用键可固定；新增条目不应导致旧键不断变化。局部润色不自动重命名整库。
- 先用 DOI/其他稳定标识发现候选重复，再比题名、作者、年份和版本。无DOI条目也可重复；相同题名或共同作者不足以自动合并。
- 同一出版版本重复导入可合并，保留使用中的键或同步所有调用；扩展稿、软件不同版本或不同DOI对象不自动合并。冲突字段先核验，不简单“最新导出覆盖”。

## 5. 开源项目、软件、网站与其他资源

先确定正文引用的对象：提出方法的论文、实际使用的软件版本、接口文档页面、数据集或协议标准。必要时分别引用，不能用其中一个代替所有证据。

| 对象 | 来源与著录重点 |
| --- | --- |
| 软件 / 开源项目 | 查该版本的 `CITATION.cff`、项目引用说明、Release及归档DOI；保留作者/团体、名称、版本、发布日期、持久链接。仓库所有者不自动等于作者，Git提交贡献者列表不自动等于署名名单 |
| 项目推荐论文 | 检查CFF的 `preferred-citation` 是否指向论文。引用其方法时采用论文；涉及实际软件版本时仍保存版本记录，必要时另引软件条目；不把论文作者和软件版本DOI混合 |
| 网页 / 文档 | 使用具体支持论断的页面，记录题名、实际责任者、发布/更新日期（若有）、URL和真实访问日期；动态页面可补已实际取得的固定版本或存档。页脚版权年份不自动是页面发布日期 |
| 数据集 / 模型 | 采用发布方版本记录和持久标识，核对制作者、版本及许可；论文介绍与具体下载数据/模型版本分开 |
| 标准 / 协议 | 记录发布机构、正式名称、编号和版本/修订日期，引用实际适用版本，不能只给组织首页 |

按学校规范及对象区分计算机程序、电子公告、报告、数据集等类型与网络载体。不要把GitHub上所有材料都标成论文或一律标成 `[EB/OL]`。`@software`、`@online` 并非所有后端都识别；确认后选兼容条目类型和字段，并验证类型标识、版本和日期确实输出。缺少年份或作者时按学校允许的缺项规则处理，不制造作者或用访问年冒充出版年。

## 6. 验证与交付

- 数据层：解析成功、引用键唯一、映射无冲突、作者顺序及数量未意外变化、必需字段和版本信息保留；运行去重与完整性检查后人工处理歧义。
- 引用层：检查实际编译入口及自定义宏，确认旧键未残留在有效调用中，没有未定义引用；区分正文未用记录、项目储备库和最终参考文献表，不靠 `nocite{*}` 凑数量。
- 输出层：使用项目原有构建链，检查日志、生成书目及PDF。覆盖本次涉及的期刊、会议、软件、网页、团体作者和多作者等类别；逐项对照校规，不将无编译报错等同于格式全部合格。
- 证据层：为本次修改条目记录“旧/新键、采用版本、来源及核验日期、作者顺序、所引论断原文位置、冲突/缺项、已做检查”。复用项目已有台账；简单单条导入无需新建整库。
- 报告实际完成范围：如“元数据已核、论点支持待核、样式输出未验证”。网络或工具不可用时交付可核实部分，不把未检查项标为通过。

## 开源项目与官方参考

2026-10-04 查阅下列项目的说明或文档。它们分别解决样式、数据管理或软件元数据问题；不是强制依赖，本技能不自动安装或替换工具，也未在本轮运行这些软件。以下流程独立编写，不包含上游代码或样式文件。

- [gbt7714-bibtex-style](https://github.com/zepinglee/gbt7714-bibtex-style)：BibTeX样式及编译入口参考；现有学校定制bst可能与该项目当前版本不同。
- [biblatex-gb7714-2015](https://github.com/hushidong/biblatex-gb7714-2015)：biblatex/Biber路径的样式和配置参考；与前一后端择其适用，不混装解决字段问题。
- [JabRef 引用键模式](https://docs.jabref.org/setup/citationkeypatterns)：可配置键生成；结构检查只能发现疑点，不能证明文献真实性。
- [Zotero Better BibTeX 引用键](https://retorque.re/zotero-better-bibtex/citing/)：稳定、固定引用键的实践参考。
- [Citation File Format schema guide](https://github.com/citation-file-format/citation-file-format/blob/main/schema-guide.md) 与 [GitHub CITATION说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-citation-files)：软件引用元数据和推荐引用对象的区别。
- [Crossref 元数据服务](https://www.crossref.org/services/metadata-delivery)：通过标识和元数据辅助核验；登记信息也需与选定原始版本核对，不替代正文阅读。
