# 结合系统上下文改进技术表述

用于计算机系统论文中的方法说明、运行过程、资源管理、算法解释及结果分析。语病的基础检查见 [中文表达](chinese-expression.md)。本指南补充技术语义判断，不要求普通段落都展开系统实现细节，也不要求研究都采用GPU场景。

## 改写前恢复最小必要上下文

先确定段落在解释什么，再读取足以消歧的定义、相邻段落及直接相关的算法、图或结果。局部请求不必通读全部工程。优先确认：

- **对象与粒度：** 当前处理的是请求、作业、阶段、线程、算子、模型实例、数据块还是设备？段落是否发生对象切换？
- **状态与动作：** 谁作出决定，谁执行动作？操作作用于逻辑记录、物理资源还是两者？动作发生前后分别成立什么条件？
- **时间与范围：** 就绪、提交、启动、完成分别在什么事件发生时成立？条件作用于一个请求、一个设备还是整个实验？
- **论证性质：** 当前句子在定义、描述实现、解释推导、提出目的，还是报告测量？确定性来自设计约束、证明还是实验？

只读取会改变本次判断的材料。上下文已明确时不反复补定义；仍不确定时保留确定部分，指出具体缺口，不选择一个常见机制填入。条件和指代可以跨句成立，不要求每句自成一套完整规格说明。

## 从代表论文观察到的表达方法

核验日期：2026-10-04。下表仅为所列正文段落的简短转述与写作分析，不是原文翻译，不代表全文审阅或认可论文的所有表述。页码为下列PDF的物理页码（从1计，USENIX文件含封面）；以节标题辅助定位。只借鉴解释方式，不向当前论文引入这些系统的机制或结果。

| 来源与实际阅读位置 | 原文组织观察 | 可迁移的写作判断 |
| --- | --- | --- |
| Kwon等，*Efficient Memory Management for Large Language Model Serving with PagedAttention*，SOSP 2023；[arXiv v1](https://arxiv.org/pdf/2309.06180v1)，§4.2–4.3，PDF第5–6页 | 先区分逻辑块与物理块，再说明块表映射，并以解码过程解释何时分配新块。 | 介绍映射类机制时，先明确两端对象，再解释触发条件和记录变化；避免只说“动态管理状态”。 |
| Xiao等，*AntMan: Dynamic Scaling on GPU Clusters for Deep Learning*，OSDI 2020；[正式论文](https://www.usenix.org/system/files/osdi20-xiao.pdf)，§3.1.2，PDF第6–7页 | 解释GpuOpManager延迟GPU算子执行，同时说明CPU算子是否继续取决于依赖。 | 区分动作直接作用的对象与依赖传播的影响，不能把局部延迟写成全作业暂停或CPU完全不受影响。 |
| Gu等，*Tiresias: A GPU Cluster Manager for Distributed Deep Learning*，NSDI 2019；[正式论文](https://www.usenix.org/system/files/nsdi19-gu.pdf)，§3.2.2，PDF第6页；§5.1–5.2.3，PDF第10–11页 | 方法段明确优先级使用已获服务量；评价分别解释JCT、利用率与排队延迟，而非以一个“性能”概括所有结果。 | 保留决策输入的可获得时点；结果段按指标和证据区分收益，不能从完成时间变化反推利用率变化。 |
| Ongaro与Ousterhout，*In Search of an Understandable Consensus Algorithm (Extended Version)*，作者2014-05-20扩展版；[作者PDF](https://raft.github.io/raft.pdf)，§5.4.2，PDF第8–9页 | 对当前任期和先前任期的日志条目分别说明提交规则。 | “多数副本”不能脱离任期条件单独成为提交结论；限定词可能决定正确性。 |
| Ghemawat、Gobioff与Leung，*The Google File System*，SOSP 2003；[作者机构PDF](https://research.google.com/archive/gfs-sosp2003.pdf)，§3.3，PDF第6–7页 | 区分原子追加与至少一次语义，并说明重试可能产生重复。 | “原子”不等于“恰好一次”，失败也不一定表示没有写入；翻译和精简须保留承诺边界。 |
| Shen等，*XSched: Preemptive Scheduling for Diverse XPUs*，OSDI 2025；[正式论文入口](https://www.usenix.org/conference/osdi25/presentation/shen-weihang)，§3、§4.1–4.2，PDF第5–6页 | 定义队列接口，再按命令的pending、in-flight、running状态区分抢占能力。 | 同一个“暂停”应结合接口层次与硬件能力解释，不能自动等同于撤销已提交命令或中断正在执行的命令。 |

这些观察由维护者综合提炼，不是各会议规定的写作模板。无需照搬英文的长句、路标或强调语气；中文按对象、条件与逻辑关系自然组织。外部论文只作表达分析来源，不能替代当前研究的事实依据。

## 容易被“润色”改变的系统语义

| 容易混写的表述 | 需要从当前材料确认的差别 |
| --- | --- |
| 预测、决定、执行 | 预测器输出估计，策略据此选择，执行组件落实动作；实际可由同一组件承担，不能凭常见架构拆造组件 |
| 就绪、可执行、已执行 | 依赖满足未必表示资源可用；获得资源也未必已经启动，具体语义由本项目定义 |
| 释放、回收、驱逐、卸载、删除 | 被移除的对象、位置和引用是否仍保留，后续恢复是否需要传输或重算；这些词不作同义轮换 |
| 配额、预留、分配、占用、利用率 | 逻辑权利与实际物理使用不同，指标定义不同；不能把配额增加直接写成有效计算增加 |
| 共享、复用、共置 | 共享什么、是否同时执行、是否只复用已有状态；共置本身不能证明无干扰 |
| 同步、异步、并行、重叠 | 调用是否阻塞、完成何时可见、实际同时推进什么；异步提交不证明传输与计算已经重叠 |
| 保证、限制、倾向、尽力 | 是硬约束、策略目标、形式结论还是测试内表现；尽力策略不能润色成确定保证 |
| 开销、延迟、完成时间、吞吐率 | 测量的对象、时间边界和聚合方式是什么；某项局部开销减少不必然带来端到端收益 |

该表用于发现歧义，不是固定术语词典。正文已有精确定义时沿用；术语合法但含义不明时先补对象和条件，而非生造更抽象的名称。

协议与存储论文还要确认承诺的语义：原子性、持久性、一致性、幂等性和交付次数各有定义。不能将一种性质作为另一种性质的语言替换；失败返回、超时与操作未发生也不等价。只在当前段落涉及这些关系时展开，不给每个系统强加分布式协议术语。

## 同一句话在不同上下文中的改写

以下均为独立构造的教学场景，不是以上论文的实现或实验，也不得直接成为用户论文事实。

**例1：状态生命周期。** 待改句：“请求结束后，系统释放缓存。”

- 上下文A：请求完成且引用计数为零时，分配器回收物理块。可写：“请求完成后，分配器回收引用计数为零的缓存块。”保留条件，不能把共享块也写成已经回收。
- 上下文B：请求尚未完成，只在等待工具；运行时将缓存移至主存以腾出显存。应写：“请求等待工具结果时，运行时将缓存移至主存，释放其占用的显存。”需要说明原句的结束时点和动作均与材料不符，不能仅换一个动词。
- 上下文C：材料只有“支持缓存释放”，没有时点、位置或共享机制。不能任选A或B；保留已知能力，在正文之外标明要核对的生命周期细节。

**例2：信息在何时可用。** 待改句：“调度器根据任务长度安排执行。”

前文若定义“长度”为提交时给出的迭代次数，可沿用该定义。若实际输入是预测执行时间，则明确写“预计执行时间”；若输入是已运行时间和资源用量，则写出相应观测量。不能因术语听起来接近，把已发生的服务量改成未知总时长；也不能将事后观察写成在线决策输入。

**例3：方法段与结果段。** 待改句：“该方法提高了资源效率。”

- 方法上下文只记录按队列长度调整批大小、尚未测量收益：写“调度器根据队列长度调整批大小。”若材料给出设计目的，可接上目的，不补效果。
- 结果上下文给出相同负载和硬件下平均请求等待时间由20 ms降至15 ms：写“在相同负载和硬件配置下，平均请求等待时间由基线的20 ms降至15 ms。”这些数字仅属本例；不能扩写为利用率或吞吐率提高。
- 摘要或章末允许概括已建立的结论，但概括需有前文依据；不能机械要求每次重复所有配置，也不能抹去改变结论的限定。

**例4：提交与完成。** 材料只说明调用返回事件句柄，后续须等待该事件才可读结果。原句“异步传输后，数据已可供计算使用”应区分提交和完成：“运行时提交异步传输，并在事件完成后使用传输结果。”没有时间线或测量时不补写“实现计算与传输重叠”。

**例5：并发下的限定条件。** 材料规定读者仍持有引用时不得回收对象。原句“对象移出索引后即可释放”应修正为“对象移出索引且不再被读者引用后，才能回收”。此处否定与条件是正确性的一部分，不能作为防御性语言删除；实际项目采用其他回收协议时，按其协议表述。

## 写成连贯段落

方法段可先给出足以定位机制的一句概括，再围绕关键事件展开必要过程，说明影响与成本。输入、状态、决策、执行和结果无需都挤进同一句，也不要求每个段落都包含全部项目。对象已明确时采用自然承前省略；动作主体或状态层次切换时再补明。

实验段先说明读者应注意的观察，再依据本次实验能区分的因素解释它。整体比较支持整体效果，受控对照可支持对应机制贡献；只有合理机制解释而缺少区分证据时，保持推断性质。审阅意见中区分作者已经给出的解释、自己提出的解释和当前数据直接支持的结论。

完成后的前后语义核对按[修订流程](revision-workflow.md)。本指南负责辨清系统对象、事件与接口承诺；实质更正须保留可定位依据。

## 从系统论文组织方法吸收的检查

以下用于整节、研究章或全文组织；局部语言修改不强制建立整套表格。来源与取舍见[语言研究来源](language-research-sources.md)。

- **限定核心主张。** 明确针对哪类工作负载、运行环境和目标，提出什么机制或认识，由哪项证据支撑。目标可以是性能、正确性、接口语义或测量发现，不统一写成“优于”。学位论文的总问题与各研究章的局部主张分别表达，不由多个主张推定层级或集成关系。
- **建立问题、设计与证据的对应。** 审阅时可列“具体限制及发生条件—相关设计决定—证据位置—支持范围”。允许一项设计解决多个问题、多项机制共同作用，以及观察本身成为贡献；不要求G1与A1逐项等数。发现缺证据时准确标出，不虚构实验或将补实验作为语言润色前提。
- **解释关键取舍。** 对影响核心结论的决定，说明可行替代、比较维度、收益、代价与适用条件。有实际意义才展开，不为每个实现细节强制写两个替代方案。事后分析可说明为什么适合当前场景，不能捏造作者曾实现、排除或测量过这些方案。
- **区分总体效果与机制解释。** 总体比较回答研究主张是否成立，机制实验回答哪些决策及条件影响结果。消融改变接口、正确性或资源配置时，应选择保持可比语义的替代方案或受控微实验；交互机制的收益不能直接相加。已有实验不足以隔离原因时按测得现象写。
- **分配正文与图注的信息。** 实验开头说明问题和比较，正文提炼主要发现与已有证据支持的解释，图注提供读图所需对象、配置、单位和口径。可以在不同层次重述关键发现，但不强制将同一数字和结论复制三遍；不预设实验一定优于基线。
- **总结获得的认识。** 从结果、条件和取舍中提炼哪些执行性质决定方法是否适用；不能把单一场景观察升级为普遍规律。学位论文可在研究章小结和总体总结中说明跨工作联系，必须有技术依据。

结构检查同时关注新意、真实状态、所得认识、设计选择、适用上下文、论述重点和表达。Levin与Redell原文还单列Focus；不把二手指南的“六维”简化当作完整分类或统一评分。理论、测量、原型与已部署系统按其真实证据类型审阅。
