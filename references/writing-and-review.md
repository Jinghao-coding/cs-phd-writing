# 写作与审阅

改写说明（2026-09-05）：整合两个上游的写作审阅流程，并按用户任务范围简化。来源及修改见 [上游改写记录](upstream-adaptation.md)。

## 按工作阶段行动

| 阶段 | 最小必要工作 |
| --- | --- |
| 讨论方案 | 阅读相关资料，给出组织建议与理由，不改正文 |
| 写段落 | 确定段落目的，核对涉及事实，以中文组织论证 |
| 改已有文字 | 读取必要上下文，定位问题，保留原意；事实更正单独说明 |
| 审阅章节 | 检查本章问题、方法与证据，再查语言及与相邻章节的接口 |
| 审阅全文 | 核对总论点、研究映射、贡献重复、术语、摘要及结论的一致性 |
| 提交前检查 | 根据本项目现行正式规范检查完整性、引用、图表与输出文件 |

### 写作

先在内部明确本节要建立的判断及证据，必要时拟段落要点，再形成正文。不向正文加入“基于用户提供的材料”“当前缺少数据”“后续补充”等维护提示。

论述应把问题、方法、证据和解释连接起来，避免仅列技术清单。材料只支持部分内容时，完成有依据的部分，在正文之外说明缺口。

摘要压缩已完成的核心研究；正文详述方法与证据；结论整合回答。三者功能不同，应核对研究对象和结论是否对应，而不是复制同一段话。

### 审阅

1. 确认所读范围和版本，找到当前稿件真正启用的内容。
2. 优先处理事实错误、矛盾、无证据断言和会改变结论的逻辑问题。
3. 检查章节功能、重复贡献、段落关系，再进行中文语义与术语检查。
4. 按当前项目规范核对图表、引文、单位及版式；区分规定、建议、偏好与尚未确认的事项。
5. 报告需要修改的实质问题。风格上的另一种写法作为可选建议，不能标成确定错误。

审阅记录按需包含：原句或位置、问题类别、原因、证据、建议。发现一个错误时扩查直接受影响的同类项，不无条件重审整篇论文。

## LaTeX、Word 与 PDF

- LaTeX 沿入口和实际 `input/include` 读取。忽略编译产物，区分注释与正文；需要材料时注意 Git 忽略目录可能被常规搜索跳过。
- 语言改写默认不动引用键、标签、公式与宏。必要的数学或结构修正属于用户请求时正常完成，并检查所有受影响的说明。
- 实际用于编译的文件遵守目标项目的同步范围，避免引入本机绝对路径或仅本地可见的材料依赖。
- Word 按请求采用对应编辑方式，保留公式、交叉引用和修订要求；不强制改用 LaTeX。
- PDF 用于阅读或对照时标明实际检查页。文字抽取无法证明版式、图形、表格都正确，涉及这些内容时查看渲染页面。

编译和导出使用目标工程已有工具。未运行的检查不能称为通过，未复现的实验不能称为复现。纯文本审阅无需为了流程完整而重新导出全文。

## 最终检查的范围

新数据检查来源与口径；新术语检查定义；章间调整检查对应目录、导引和结论；图表调整检查正文提及、标号、单位及来源。只读评审报告不能宣称已经修好原稿。

已完成检查应报告范围和材料依据。需要后续事实确认时，保留清楚的待核记录，同时继续完成其他已获授权且可确定的工作。
