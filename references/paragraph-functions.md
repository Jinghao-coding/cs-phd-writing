# 段落功能与论证组织

改写说明（2026-09-05）：参考 doctoral-dissertation-skills 的 [paragraph_functions.md](https://github.com/syc9336-rgb/doctoral-dissertation-skills/blob/95b0af625e34e4d26835e719352c52c2e907a43c/skills/doctoral-dissertation/references/paragraph_functions.md)，按计算机学位论文重新编排，补充算法、系统、证明、消融及多成果整合。来源许可见 [上游记录](upstream-adaptation.md)。

用于新写段落、重组章节或检查论证缺口。先判断本段要让读者明确什么，再核对已有材料是否足以支持；写作时只选择相关功能。功能可以跨段完成，一段也可保留必要的定义或限定，不按下表顺序凑段，不要求每段套同一种句型。

## 建立问题与概念

| 功能 | 需要组织的内容 | 核对重点 |
| --- | --- | --- |
| 交代背景 | 当前场景、发生的变化、受到影响的对象与具体问题 | 背景事实可定位，宏观趋势确实影响所研究对象 |
| 收束问题 | 已有解决办法、在本场景中的不足、本研究选择处理的范围 | 区分材料未涉及的问题和已有研究尚未解决的问题 |
| 定义概念 | 名称、对象、含义、相邻概念的区别，必要时给出单位或形式定义 | 译名稳定；不能把不同指标合并为同一概念 |
| 引入理论或模型 | 所用关系、成立条件、对当前问题的解释或建模作用 | 说明模型适用性；保留必要假设及来源 |
| 比较文献 | 在共同问题下比较机制、条件与证据，解释结果差异 | 不能按作者排队复述；不同条件下的数字不能直接排序 |
| 提出研究问题 | 待回答的具体判断、研究对象和边界，以及所需验证 | 研究目标不能提前写成已实现收益 |

## 说明方法与实现

| 功能 | 需要组织的内容 | 核对重点 |
| --- | --- | --- |
| 描述系统模型 | 实体、状态、输入输出、约束及相互关系 | 概念框架与实际软件接口分别说明 |
| 解释设计选择 | 需要解决的困难、选用机制、理由与代价 | 比较真实备选方案，不虚构其他方法的缺陷 |
| 解释算法 | 决策依据、状态变化、关键步骤及终止条件 | 文字与伪代码一致，不把算法步骤改成口号 |
| 陈述命题与证明 | 明确假设和结论，给出必要推理步骤与证明依据 | 数学推导正常保留；实验观察不能替代普遍性证明 |
| 交代实现 | 实际组件、接口、数据流及相关配置 | 已实现、模拟和计划中的功能分别表述 |
| 说明实验设计 | 要检验的问题、对象与数据、基线、指标及对照安排 | 已运行设置与拟议实验区分；只列本研究需要的验证 |

## 报告证据与解释

| 功能 | 需要组织的内容 | 核对重点 |
| --- | --- | --- |
| 报告结果 | 在给定条件下对研究问题的回答、关键数据及图表位置 | 数值、单位、方向、基线和已有不确定性信息完整 |
| 解释图表 | 指出应观察的部分、主要差异及其对当前问题的含义 | 不逐项复述全部数据；解释不能超出图表及其他证据 |
| 分析消融 | 改变了什么、其余条件如何保持、观察到何种差异 | 多因素同时变化时，不把收益归给某个单独组件 |
| 分析开销与规模 | 成本、性能随测试规模的变化及实际瓶颈证据 | 不从少量规模点推出未经验证的渐近规律或无限扩展能力 |
| 处理不符预期的结果 | 实际方向、已有误差或不确定性、可能解释及可支持结论 | “未观察到差异”不等于“证明没有影响”；不补造统计检验 |
| 讨论机制 | 观察结果、相关机制、支持该解释的证据与其他可能解释 | 有证据的解释与待验证假设分清，不用合理故事代替因果验证 |
| 综合多项证据 | 不同工作各自回答的问题、互补之处及能够共同支持的判断 | 没有联合实验时不编造整体收益，不重复计算会议版与扩展版 |
| 分析访谈或用户研究 | 从实际材料提出主题，用原始证据说明共性、差异与反例 | 仅在项目确有此类研究时使用；不生成受访者引语 |

## 回到章节与全文

| 功能 | 需要组织的内容 | 核对重点 |
| --- | --- | --- |
| 说明贡献 | 既有认识或方法的具体不足、本研究支持的新认识或能力及适用范围 | 贡献不能只列使用了哪些技术，也不能只重复提升数字 |
| 交代局限 | 实际约束、它影响哪项推断、仍成立的结论及未覆盖范围 | 当前结果的必要限定就地保留；一般局限集中讨论 |
| 提出后续研究 | 尚未回答的问题、继续研究的理由和需要的具体验证 | 提出可执行方向，避免每段机械追加泛泛展望 |
| 组织章首与章末 | 章首定位本章问题；章末归纳已经建立的认识及其与全文的关系 | 保留有用导引；并列章节无需编造前后依赖 |

## 如何使用

1. 先读上下文、已有大纲和相关证据，确定本段在章与节中的作用。
2. 选择相关功能，列出已有材料能够支持的要点；材料缺口只记在正文之外。
3. 按中文语义组织段落。方法、结果和解释挤在一起时，按理解需要拆开，不追求固定句数。
4. 检查中心判断是否明确、证据是否支持、解释是否必要，以及相邻段落是否重复。

例如，原始材料只有负载 L 下方法 M 的等待时间数据时，可以写结果段；没有网络观测或消融证据，就不能增加“通过缓解网络拥塞取得收益”的机制结论。需要方法说明时回到算法与实现材料，不能从结果数值反推未记录的设计。
