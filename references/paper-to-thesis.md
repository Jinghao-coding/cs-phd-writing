# 英文小论文到中文学位论文

把真实研究成果组织成能够回答全篇问题的中文学位论文。转换涉及研究主线、章节功能、论证顺序、表达和证据归属；单段翻译按局部任务处理，不强制走完整成果整理流程。

## 先确定交付层次

- **组织方案：** 给出研究主线、成果与章节对应、可合并或拆分的内容及依据，不写入正文。
- **章节转写：** 按已确认结构，将指定英文内容改写为中文博士论文正文，保留技术含义与来源。
- **多稿整合：** 处理共享背景、重复方法、扩展稿、符号与引文，并核对整章或全篇的一致性。

用户已确认的题目和章节约束从项目配置读取。开题计划、投稿状态和师兄范文不自动成为当前成果事实。输入读取见 [输入读取](input-reading.md)，事实核对见 [事实与术语](evidence-and-terms.md)。

## 1. 明确每项研究与选定版本

利用已有材料索引，必要时建立 [成果与章节对应表](../assets/project-template/docs/paper-to-thesis-map.md)。记录研究问题、方法、证据位置、实验条件、当前版本、出版状态和已确认的本人贡献。

会议稿、期刊扩展稿、预印本和在写稿可能属于同一研究。按方法与证据的实际增量区分基础和扩展，不按文件数或标题数重复计算贡献。出版状态只采用有依据的当前记录；共同作者的贡献不得推定为本人独立完成。

## 2. 形成论文主线与章节功能

先回答全篇研究问题，再说明各项工作处理哪个层次、对象或条件。允许并列、互补、递进及前期基础关系；只在有证据时写成方法依赖或系统集成。

| 材料关系 | 可采用的组织方式 |
| --- | --- |
| 多篇成果共同回答一个问题 | 合并支撑同一研究章，说明各自作用和证据 |
| 一个工作涉及多个论证任务 | 按需要放入基础、方法或验证部分，避免重复报告同一贡献 |
| 会议版及其扩展版 | 合并梳理基础方法与新增问题、方法或实验 |
| 前期探索或有限支撑 | 作为研究基础、相关方法或补充材料；遵守用户明确的不单独成章安排 |
| 尚无集成或联合实验 | 分别陈述已有结果，不虚构统一系统验证 |

参考范文时提取问题分解和论证功能；章数、顺序与具体方法由当前材料决定。更多结构判断见 [论文结构](thesis-structure.md)。

## 3. 重组小论文内容

| 原论文内容 | 学位论文中的处理 |
| --- | --- |
| Abstract / Introduction | 提取问题、动机与贡献；按全篇和研究章需要重新组织，消除重复背景与宣传性包装 |
| Related Work / Background | 按研究问题或技术路线整合；共享概念集中定义，保留各章确有必要的区别 |
| Method / System | 明确本章问题、假设、输入输出、机制和设计依据；补足材料中已有但原论文因篇幅省略的解释，不补造方法 |
| Experiments / Evaluation | 保留对应版本的环境、数据、基线、指标和结果；围绕本章要回答的问题排列证据 |
| Conclusion | 转为本章结论及全篇综合回答；不重复复制每篇论文的总结或新增未经论证的成果 |

转写后校准 we、this paper、our method 对应的主体：整篇学位论文、当前章、具体方法各有范围。中文表达按 [中文表达](chinese-expression.md) 检查。

## 4. 处理跨稿一致性与来源

- 同一概念统一术语，同一符号核对含义。整合确需更改公式符号、引用键或标签时，保留对应关系并检查所有受影响位置；仅做语言编辑时沿用原有技术内容。
- 合并重复文献条目，按当前项目规范著录。图表题注、坐标、单位及正文提及须同步；翻译题注不能改变指标或实验含义。
- 不同论文的硬件、负载、数据集或基线不一致时，不能把数字合并成可直接比较的排名，也不能相加各自的提升比例。
- 保留原论文及版本定位，按项目要求说明已发表内容与本人贡献。来源映射可留在维护文档中；正文使用学校要求的引用或成果说明形式。
- 真实论文中已有的科学限制正常写入对应论述。材料缺口、写作待办和版本管理说明放在正文之外。

## 5. 验证组织转换

检查每章是否回答明确问题，贡献是否重复计算，章间关系是否有依据；再核对原稿与转写稿的研究对象、假设、条件、数值、比较方向和确定性。

交付应与请求相符：方案提供对应表和理由，转写提供实际正文，审阅提供可定位问题。不能把目录生成称为完成论文转换，也不能把全文翻译称为已完成论证整合。结构、引用或版式修改后的检查遵循 [写作与审阅](writing-and-review.md)。
